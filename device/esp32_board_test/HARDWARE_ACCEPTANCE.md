# B 板硬件接入与采样验收

2026-09-23：用户确认 ADS1115、LED、蜂鸣器均未接。B 板在线，主动采样返回相同请求编号的 `sensor_read_error`；缺模块时的错误链路已验证，采样本身尚未通过。保持现有 0.5.0 固件，无需为接模块重新烧录。

## 1. 断电后接 ADS1115

先拔掉 B 板供电。下面按模块丝印接线，不按芯片脚序猜测排针位置：

| ADS1115 模块 | B 板连接点 |
|---|---|
| VDD / VCC | 3V3 |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |
| ADDR | GND（当前固件地址 0x48） |
| A0 / AIN0 | GND（首次做零输入检查） |
| ALERT/RDY、A1、A2、A3 | 此步骤不接 |

确认模块的 I2C 上拉电阻接到 3.3V，而不是 5V。GPIO21/22 是 B 板现有固件配置，不要接到 A 板摄像头引脚。

ADS1115 正常模拟输入应在 GND 与 VDD 之间；PGA 的 ±6.144V 满量程不代表可以在 3.3V 供电时输入 6V，也不允许直接输入负电压。首次不要连接实际 RLC 交流波形或未知实验信号。依据：[TI ADS1115 数据手册](https://www.ti.com/lit/ds/symlink/ads1115.pdf)。

## 2. 上电与通信检查

两板和电脑连接热点 `sa`，保持 Broker、HTTP 服务各一个实例。B 会自动重试 ADS1115 初始化；心跳 `ads_initialized` 应变为 true。若仍为 false，断电检查供电、共地、SDA/SCL 和 ADDR，不能仅靠改软件把状态标为成功。

从 `cloud` 目录运行：

```powershell
.\.venv\Scripts\python.exe -m tools.check_sensor --count 100
```

每个请求只接受相同 request_id 的 A0 原始数据；自动采样和之前请求的消息不能充数。出现设备告警、超时、空值或无效数据则失败，退出码为 1。JSON 证据默认保存在 `cloud/data/acceptance/sensor-时间-编号.json`；包含全部原始读数、均值、最小/最大值和标准差。未校准时仍保留 `quality=degraded/calibrated=false`。

## 3. 参考电压检查与校准准备

零输入检查完成后，断电移除 A0 到 GND 的短接。用共地、稳定且处于 0–3.3V 之间的直流源接 A0，并用万用表实测同一点。不要直接把未经测量的电源标称值当成校准标准。

工具支持同时指定 `--reference-voltage`（万用表读数，单位 V）和 `--max-error`（本次验收约定的最大绝对误差，单位 V），并检查每个读数。两项必须一起填写；阈值应根据项目精度目标和参考仪器确定，工具不会自行宣称达到某个精度等级。

至少记录零点及两个不同非零参考点、每点多次读数、万用表型号/量程、模块供电电压和接线状态。先评估偏移、增益与重复性，再决定校准参数。这个工具只采集和比较，不自动修改固件校准系数，也不会把一次测试通过标成已校准。

ADS1115 最大转换速率为 860 SPS，本项目目前每 5 秒发布一次自动采样，适用于直流和慢变化观测；快速 RLC 波形仍用示波器。规格依据同一份 TI 数据手册。
